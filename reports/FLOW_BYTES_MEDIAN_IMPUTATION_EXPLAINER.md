## 1. What Was the Problem in the Dataset?

When examining network traffic flow files (generated by **CICFlowMeter**), columns such as:
- `Flow Bytes/s` (Byte transfer rate)
- `Flow Packets/s` (Packet transfer rate)

frequently contained values that were:
1. **Literal text strings:** `"Infinity"` or `inf`
2. **Missing / Unfilled values:** `NaN` or empty blank cells
3. **Zero values:** `0` or `0.0`

### Why Did This Happen? (The Root Cause)
In network flow monitoring, the rate is calculated using basic division:

$$\text{Flow Bytes/s} = \frac{\text{Total Volume of Transferred Bytes}}{\text{Flow Duration}}$$

$$\text{Flow Packets/s} = \frac{\text{Total Number of Packets}}{\text{Flow Duration}}$$

- **Microsecond Precision:** Network flow meters measure duration in microseconds ($\mu$s).
- **Instantaneous Traffic:** During flood attacks (such as **DoS-SYN Flood**, **DDoS-ACK Fragmentation**) or single-packet port scans, packets arrive within the exact same microsecond, or the duration is rounded down to `0`.
- **Division by Zero:** 
  $$\frac{\text{Bytes}}{0} \longrightarrow \infty \text{ (Infinity)}$$
- Standard CSV parsers in Python / Pandas either import these as `np.inf`, or if unhandled, throw errors, or treat them as blank strings (`NaN`).
- **Machine Learning Impact:** Machine learning algorithms (Logistic Regression, Random Forest, SVM, Neural Networks) cannot compute math on `Infinity` or `NaN`. Feeding them directly causes training crashes (`ValueError: Input contains NaN, infinity or a value too large for dtype('float64')`).

## 2. Why Impute with the "Median" Instead of Mean or 0?

When dealing with missing or infinite values, data scientists typically choose between:
1. **Dropping the rows:** ❌ Bad idea. You would delete thousands of legitimate DoS/DDoS attack samples, causing your model to become blind to flood attacks.
2. **Replacing with 0:** ⚠️ Suboptimal. A flow that transferred real packets did not have zero transfer speed; it was an instantaneous transmission. Setting it to 0 creates artificial skew and falsifies network physics.
3. **Imputing with Mean (Average):** ❌ Problematic. Network transfer rates have extreme **outliers**. A few large file downloads (e.g., streaming or large payloads) can reach $200,000,000$ Bytes/s ($200$ MB/s), dragging the average unnaturally high.
4. **Imputing with Median:** ✅ **The Gold Standard.**
   - The median represents the exact 50th percentile (the middle flow).
   - It is completely immune to extreme outliers.
   - It preserves the natural distribution of typical campus and IoT network flows without biasing the ML classifier.

## 4. Where Were the Changes Made in the Project?

The data cleaning and feature preparation scripts handle this transformation systematically:

### 1. `scripts/prepare_features_week4.py` (Lines 322–334)
```python
# Replace infs in Flow Bytes/s and Flow Packets/s with NaN, then impute with median/0
for col in ["Flow Bytes/s", "Flow Packets/s"]:
    if col in chunk.columns:
        chunk[col] = pd.to_numeric(chunk[col], errors='coerce')
        chunk[col] = chunk[col].replace([np.inf, -np.inf], np.nan)

# Fill missing values with median or numeric fallback
chunk_feats = chunk_feats.apply(pd.to_numeric, errors='coerce').fillna(median_val)
```

### 2. `scripts/feature_pipeline.py` (Lines 49–56)
A reusable transformer pipeline (`LightweightFeaturePipeline`) ensures that any incoming test flow or streaming chunk has `inf` stripped and converted before reaching the ML model:
```python
for col in ["Flow Bytes/s", "Flow Packets/s"]:
    if col in clean_df.columns:

avail_features = [c for c in self.candidate_features if c in clean_df.columns]
```
